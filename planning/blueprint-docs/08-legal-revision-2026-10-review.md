**ステータス: ドラフト（顧問弁護士の確認前）。確認が済むまで main へマージせず、公開しない。**

この改訂案は確定した法務文書ではない。事実関係を集めて叩き台を作ったもので、法的な判断は下の「判断をお願いしたい点」に残している。

## 背景

- Grift は 2026-09〜10 に旧 Web アプリ（見積支援・GitHub 実績分析のベータ版）を停止し、OSS の CLI（`grift-cli`、MIT）と、人材紹介会社・SES 向けの個別見積の試行（PoC）に切り替えた。正式版は 2027 年の提供を目指す。Team Beta / Paid Trial / Estimate Audit は取り下げた（[ADR-0005](../../docs/adr/ADR-0005-grift-cli-pivot.md)）。
- `/privacy`・`/terms` には旧 Web アプリ前提の記述が残っていた（GitHub 連携、見積・提案支援、ベータ版、Enterprise プラン、有料β、生成結果の免責など）。ADR-0005 の「影響」で、法務の確認を経て別途改訂するとしていた。

## 改訂の要点

### 削除した記述

- GitHub 連携情報の取得・利用（旧 第7項）、案件・見積・提案情報と生成物（旧 第8項）、テナント分離と匿名化（旧 第9項）、学習利用の方針（旧 第10項）、未成年者（旧 第15項）
- 規約: ベータ版であること、登録・アカウント、料金・Enterprise・有料β・見積監査、生成結果・分析結果の免責、秘密情報、利用停止・登録抹消、退会、利用料金 3 か月分を上限とする責任制限

### 追加・変更した記述

- **適用範囲を実態に合わせた**: (1) LP の閲覧、(2) LP から移った先の Cor AI 受付での相談、(3) 紹介会社さまとの試行。
- **LP が実際に取得する情報**: LP には入力フォームがない。全ページで Google アナリティクスと Microsoft Clarity を読み込んでいるため、両ツールを提供者、送信される情報、目的、オプトアウトの方法とあわせて明記した。
- **AI 受付**: CTA は cor-jp.com の AI 受付へ移る（intent・source・UTM を URL で渡し、個人を識別する情報は含まない）。そこで受け取った情報は全社の個人情報保護方針に従う。AI 受付が生成 AI を使うこと、候補者の個人情報を入力しないでほしいことを書いた。
- **Grift CLI**: 利用は MIT ライセンスだけに従う。当社への自動送信はない。ネットワークに出るのは利用者が明示した操作だけ。他人の履歴を計測するときは本人の同意が要る（利用規範）。
- **試行（PoC）**: 個別契約で、扱う情報、目的、保管期間、削除方法、本人同意の取り方を定める。個別契約が本ポリシー・本規約に優先する。サイト上の説明は契約の申込みではない。
- **正式版**: 2027 年を目指すが、内容・価格・時期は未定で変わりうると書いた。
- **第三者提供**: 全社方針と同じ 4 つの例外にそろえた。旧版の「業務委託先に提供する場合」は第三者提供の例外ではないので、委託の項に移した。
- **外国にある第三者（法 28 条）、開示等の請求**: 全社方針の手続を参照する形にした。
- **免責**: 消費者契約法 8 条を踏まえ、消費者契約に当たる場合のただし書きを加えた。
- **社名表記**: ADR-0005 に合わせ、「Cor株式会社（Cor.inc）」を「Cor.株式会社」に変えた。
- 末尾に制定日・改定日の履歴を加えた。

## 顧問弁護士に判断をお願いしたい点

### プライバシーポリシー

- **P1（公開前に必須）旧 Web アプリで取得した情報**: 2026-02〜09 の旧 Web アプリで取得した情報（GitHub 連携の repository 情報、案件・見積情報、利用者情報）を削除したか、まだ持っているかを確認する。持っているなら、利用目的と取扱いをどこかに残す必要がある。削除したなら、その旨を書くかどうか。ドラフトにはどちらも書いていない。
- **P2 二層構成**: 全社の個人情報保護方針を基本にし、本ポリシーは Grift 固有の事項だけを定める（定めがなければ全社方針による）構成でよいか。両者の記載が違うときにどちらを優先するか。
- **P3 アクセス解析と外部送信**: GA4・Clarity への送信を、個人関連情報（法 31 条）の第三者提供として整理するか、委託として整理するか。自社商品の紹介サイトとして電気通信事業法の外部送信規律（27 条の 12）の対象外と整理してよいか。対象外でも、同じ程度の内容を公表しておく方針でよいか。
- **P4 ツール提供者の規約が求める開示**: Microsoft Clarity と Google アナリティクスの利用規約は、プライバシーポリシーでの開示を求めている。ドラフトの記載で足りるか（Clarity の推奨文言にある Microsoft Advertising への言及が要るかを含む）。
- **P5 AI 受付の情報**: 全社方針には、AI 受付で生成 AI やメール送信サービスを使うことや保存期間の記載がない。全社方針に足すか、Grift 側に事業者名や保存期間まで書くか。
- **P6 試行での候補者データ**: 試行で候補者の個人データを扱う場合に、委託と第三者提供のどちらとして整理するか。本人同意を紹介会社さまと当社のどちらが取るか。職業安定法 5 条の 5 と関係する指針（求職者の個人情報の取扱い）との関係。個別契約のひな形が要るか。
- **P7 学習利用**: 旧版にあった「無断で学習用途に利用する前提ではありません」を削除した。AI 受付で受け取った情報などについて、学習に使うかどうかを明記するか。
- **P8 外国移転（法 28 条）**: 本文で米国の事業者であることを示し、詳しい情報は求めに応じて提供するとした。この書き方で足りるか。
- **P9 削除した項目**: 未成年者の項を削除した（B2B が中心のため）。この扱いでよいか。
- **P10 個人情報保護管理者**: 全社方針には記載がある。Grift 側にも書くか。

### 利用規約

- **T1 規約の性格**: 閲覧だけのサイトで「本規約に同意のうえ利用する」と定めることの効力。定型約款に当たるか、変更の手続（民法 548 条の 4）をどうするか。
- **T2 Grift CLI と利用規範**: CLI には MIT ライセンスだけを適用し、本規約では制限しない整理でよいか。利用規範（norms）は法的拘束力のない「準拠・非準拠」の基準として扱い、遵守は試行の個別契約で求める方針でよいか。
- **T3 試行**: サイト上の説明は申込みの誘引で、契約は個別契約で結び、個別契約を優先する整理でよいか。
- **T4 免責**: 消費者契約法 8 条・10 条を踏まえてただし書きを入れた。無償のサイトとして、これで必要十分か。
- **T5 削除した条項**: 秘密保持、利用停止、反社会的勢力の排除、料金は、個別契約で定める前提で削除した。サイトの規約に残すべきものはあるか。
- **T6 経過措置**: 旧 Web アプリの利用者や、有料β・見積監査を契約した相手が実在した場合、附則で経過措置を定める必要があるか。
- **T7 名称・ロゴ**: 「Grift」の商標登録の状況と、第 8 項の書き方。
- **T8 合意管轄**: 消費者との関係で、専属的合意管轄の定めが有効か。
- **P11 著作権表示**（F7）: grift-cli の著作権表示が「TEP contributors」になっている。LP では当社が公開していると説明しているので、当社の名義にそろえるかどうか。
