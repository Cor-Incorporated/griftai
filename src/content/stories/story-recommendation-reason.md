## 「この方の強みは、具体的に何ですか？」

人材紹介会社でITエンジニアを担当している佐藤さん（仮名）は、その日の午後、取引先の開発会社から電話を受けました。

先週推薦したバックエンドエンジニアの田中さん（仮名）について、「書類は拝見しました。ところで、この方の強みは具体的に何ですか？」と聞かれたのです。

推薦文には、こう書いていました。

> Java・Spring Bootでの開発経験が5年あり、詳細設計からテストまで一通り担当されています。面談では受け答えが丁寧で、真面目な方という印象です。

嘘は書いていません。ただ、読み返すと、どの候補者にも当てはまりそうな文章でした。佐藤さんは「丁寧に仕事をされる方です」と繰り返すしかなく、電話を切ったあと、少し落ち込みました。

## 足りなかったのは「確かめられる材料」

佐藤さんが持っていた材料は、経歴書と、1時間の面談の印象だけです。経歴書には本人が書いた年数と担当工程が並び、面談では本人の話しぶりが分かります。どちらも大切な材料ですが、企業の担当者が自分で確かめられるものではありません。

企業から見れば、「真面目な方です」は営業の感想です。感想をいくら重ねても、推薦の理由は具体的になりません。

## 候補者本人に、手元で実行してもらう

翌週、佐藤さんは田中さんに相談しました。「田中さんが公開しているリポジトリで、Grift CLIを実行してみてもらえませんか。結果を共有するかどうかは、田中さんが決めてください」。

田中さんは、休日に続けている公開リポジトリで、自分のPCから次のように実行しました。

```bash
pipx install grift-cli
cd your-repo
grift report
```

Griftはリポジトリのgit履歴だけを読み、計測にAI（LLM）は使いません。結果は田中さんのPCの `.grift/` に保存され、どこにも送られません。田中さんは結果を読んだうえで、このリポジトリの記録を共有することにしました。

共有された記録には、たとえば次のような値が並んでいました（数値は説明のための例です）。

- 本番コードを変えたコミット138件のうち、58件で同じコミットのテストも変更していた（test co-change 0.42、58 of 138）
- コミットは、本人の仕事・bot・自動生成物などに分けて数えられていた
- 観測した期間と、使ったGriftのバージョンが書かれていた

点数や順位はありません。あるのは、分子と分母と、測った条件です。

## 推薦文に、検算できる1行を足す

佐藤さんは推薦文を書き直しました。

> 本人が共有した公開リポジトリでは、本番コードを変えた138件のうち58件で、同じコミットでテストも変更しています（Grift CLIで計測。受け取った側がgrift verifyで再計算できます）。面談では、どんなときにテストを書き足すのかを聞いてみてください。

企業の担当者は、この数値を「良い・悪い」と判定する材料としてではなく、面談で聞くことの手がかりとして受け取りました。次の面談では、テストを書くときの判断の基準について、具体的なやり取りがあったそうです。

## この物語で伝えたいこと

- Griftは、推薦の理由をつくる「材料」を足すものです。人を評価したり、合否を決めたりはしません
- 実行するのも、何を共有するかを決めるのも、候補者本人です。共有されたのが本人の選んだリポジトリの記録であることも、あわせて伝えます
- 1つの数値だけで判断しないでください。数値は、面談で聞くことを具体的にするために使います
