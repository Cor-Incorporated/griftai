# ADR-0006 LP の最初の画面と計測：離脱を減らし、問い合わせまでを数える

## ステータス: Proposed (2026-10-26)

ADR-0005 の決定 2（CTA）のうち、トップのヒーローのボタンをこの ADR で改める。

## 背景

- 社内の分析にもとづき、griftai.org のトップからの離脱を減らし、問い合わせを増やす改修をすることにした（2026-10-26、代表）。数値と分析の詳細は社内の文書にある。
- 調べると、文言より前に、技術的な原因が 2 つ見つかった。
  - 2026-09-16（#70）から、ページの初期化を `astro:page-load` だけで始めていた。最初の訪問での `astro:page-load` は window の `load`（画像と外部スクリプトの読み込みの完了）まで来ない。そのため、回線が遅いとヒーローが白いままだった。ヘッダーのロゴ 2 枚（1024px、合わせて約 1.9MB）がこれをさらに遅らせていた。Slow 4G 相当の回線では、ヒーローが見えるまで約 12 秒かかっていた（#82）。
  - GA4 と Clarity のタグをどのホストでも読み込んでいた。手元の開発・CI の e2e・Cloudflare Pages のプレビューで開いたページも、本番と同じプロパティに送られていた（#83）。
- 最初の画面は CLI を使うエンジニア向けの言い方だった（小見出しが「Grift CLI ・ OSS（MITライセンス）」、2 つめのボタンが GitHub）。ADR-0005 で狙う人材紹介会社・SES の営業には、誰のためのものかが分かりにくかった。
- 資料はフォームなしでダウンロードできる（2026-10-20 の SEO の定例で決めたこと）。そのため、資料を取った人の数がどこにも残っていなかった。問い合わせの CTA は Cor.株式会社の AI 受付（別のサイト）へ移るので、griftai.org の側では、どの CTA が押されたかも見られなかった。

## 決定

1. 最初の画面はスクリプトを待たずに HTML と CSS だけで出す。ヒーローはフェードインの対象にしない。ページの初期化は `astro:page-load` だけで書かず、`src/lib/page-ready.ts` の `onPageReady` を使う（最初の表示ではすぐに、ページ遷移のあとは `astro:page-load` で実行する）。e2e で、画像と外部スクリプトの読み込みを止めたままヒーローが見えることを確かめ続ける。
2. 最初の画面には読み手（人材紹介会社・SES の営業。2026-10-26 から自社開発企業の採用担当も含む。ADR-0005 の改訂）を先に書く。ボタンは「自社でテストしてみる」と「資料をダウンロード」の 2 つにする。エンジニアの方向けの「GitHubでGrift CLIを見る」は、ヒーローでは文字のリンクにして残す。最後の CTA・フッター・料金のカードは、これまでどおり GitHub のボタンを置く。
3. ボタンの下に、テストの範囲と費用は個別に案内すること、申し込みは Cor.株式会社の AI 受付で受け付けることを書く。押した先が別のサイト（AI 受付）だと、押す前に分かるようにする。
4. CLI の使い方の例（コマンド）は最初の画面から外し、「観測すること」の下に置く。CLI の事実（版・ライセンス・コマンド・指標）の中身は変えない。CLI の事実は ADR-0005 の決定 7 のとおり、CLI の担当が直す。
5. 同じボタンを並べたブロックは、同じページに 2 つ置かない（トップの末尾の「次の一歩」を外した）。
6. GA4 と Clarity のタグは本番のホスト（`src/config/analytics.ts` の `productionHosts`）でだけ読み込む。CI のビルドがそのまま本番に出るので、ビルドのときではなく開いたページのホスト名で判定する。
7. 成果のイベントは次の 2 つにする。フォームは足さない。電話番号とメールアドレスは送らない。
   - `cta_click`: Cor.株式会社の AI 受付・電話・メールへのリンクのクリック（`cta_method`、`cta_source`、`cta_intent`）
   - `deck_download`: 資料の PDF のクリック（`file_name`、`placement`）

## 理由

- 最初の画面が白いと、文言をどう直しても読まれない。直すのは文言より先にした。
- 広告や直接アクセスで来た人は、最初の画面だけを見て残るかどうかを決める。誰のためのものかが分からなければ、合う人も離れる。合わない人には早く分かるほうがよい。
- 問い合わせ（チャット）は最初に訪れた人には重い。問い合わせより軽い次の一歩として資料を選んだ（2026-10-20）ので、ボタンにして問い合わせの隣に置く。
- 数えられないものは直せない。フォームを置かずに数えるには、クリックをイベントにするのがいちばん小さい変更だった。

## 判断を待つこと

代表の判断が要るので、この ADR では決めていない。

| 論点 | 選択肢 | いまの扱い |
|---|---|---|
| 資料請求の形 | フォームなしのまま／メールアドレスなどと引き換えにする | フォームなし（2026-10-20 の決定）。`deck_download` の数を見てから決める |
| 広告の出し先 | いまの区分のまま／人材紹介・SES の営業に関心のある人に絞る／配信先を見直す | 運用会社の側の設定。こちらからは変えず、案を社内の文書に書いた |
| 資料の PDF | 2026 年 8 月（v0.5）の版に注記したまま／作り直す | 注記したまま。中身の CLI の事実はこの改修では書き換えない |
| 取引実績の会社の掲載 | 許諾を取って載せる／載せない | 許諾が要るので、いまは載せない |
| トップをさらに短くするか | 「Griftとは」「3つの約束」「使う人ごとに」などをまとめる、並びを変える | 今回は重なる 1 か所だけを外した |
| GMO のコラムの話題 | AI の見積もり・要件定義の話題のまま／いまの Grift に合わせて書き換える | 変えていない（題名と見出しのキーワードを残す決まり） |

## 影響

- 新しく初期化を書くときは `onPageReady` を使う。`astro:page-load` だけで書くと、最初の訪問で `load` まで動かない。
- 手元・CI・プレビューで開いたページは、GA4 と Clarity に送られない。2026-10-26 より前の記録には、そうした訪問（ホスト名が `localhost` や `*.pages.dev`）が入っている。過去の数値を見るときは、ホスト名で絞り込む。
- GA4 の管理画面で、`cta_click` と `deck_download` をキーイベントにし、`cta_source`・`cta_method`・`placement` をカスタム ディメンションに登録すると、レポートで見られる（代表のログインが要る）。
- e2e smoke は、最初の画面（読み手の名前・2 つのボタン・読み込みを待たないこと）と、計測（本番のホストだけでタグを読み込むこと・イベント）を検査する。

## 代替案

- フェードインをすべてやめる: ほかのセクションの演出は #70 で決めたことなので残し、最初の画面だけを外した。
- IntersectionObserver に戻す: 2026-09-16 に、CI の速いスクロールで取りこぼして不安定だったため、スクロール位置での判定を残した。
- タグをビルドのときの環境変数で切り替える: CI の e2e で使ったビルドを、そのまま本番に出しているので区別できない。
